架构方案选择

三种方案，权衡开发速度 vs 功能完整性

A

静态视频 Demo

最快出效果，1-2天可完成

数字人用预录 MP4 视频直接嵌入页面，JSON 时间轴驱动视频进度 + 讲义翻页同步。学生摄像头用浏览器原生 API。不接 ZEGO，无后端。

优点

  • 零 API 依赖，最快交付
  • 纯前端，部署简单
  • 演示完整三分屏效果

缺点

  • 无真实 RTC 互动
  • 数字人是死视频，不能实时回应
  • demo 结束后要重建
B

完整 ZEGO 混合方案 ⭐ 推荐

真实可用的产品架构，适合正式 demo

录播段：ZEGO 数字人离线生成视频流式播放；互动段：ZEGO Streaming Avatar RTC 实时数字人。JSON 时间轴控制两种模式切换 + 讲义同步。Next.js API Routes 管理课程编排。

优点

  • 真实技术栈，可直接演进为产品
  • 数字人互动段有真实 RTC
  • 架构完整，可扩展

缺点

  • 依赖 ZEGO API，需先调通
  • 开发周期约 1 周
  • 需要后端 API Routes
C

前端 Player + ZEGO 仅 RTC

折中方案，突出互动体验

录播段用本地预录视频，互动段切换到 ZEGO Streaming Avatar。只集成 ZEGO 的 RTC 部分，时间轴完全在客户端驱动，无后端。

优点

  • 有真实 ZEGO 数字人互动
  • 无需后端
  • 复杂度适中

缺点

  • 录播段仍是 mock 视频
  • 后期需重构后端部分
